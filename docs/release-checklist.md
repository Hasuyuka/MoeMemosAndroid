# 发版前检查清单

> 目标：让"发完才发现"变成"发之前就发现"。整个清单 5 分钟能走完，不要跳。

## 1. 代码侧（CI 会做，但确认它真的做了）

- [ ] 分支 → PR → **CI 绿**（`build + unit tests`）
- [ ] PR 里没有夹带调试代码（`Timber.d` 临时日志、屏幕上的诊断浮层、`TODO`)
- [ ] 新增的中文字符串**三处都加**了：`values`、`values-zh-rCN`、`values-zh-rTW`
- [ ] 涉及数据库结构的改动有对应的 migration 测试

## 2. 打 tag 之前先自己装一遍

从分支的 CI 产物下载 `app-debug.apk`（Actions 页面），装到测试机上：

```powershell
adb install -r -d app-debug.apk      # -d：debug 包 versionCode 比正式版低
```

装完跑下面这套冒烟。**这一步不能省** —— 发出去的包和你验过的包要是同一个提交。

## 3. 冒烟清单（真机，2 分钟）

数据准备：至少 20 条备忘，其中一条带 5 张以上图片。

- [ ] **建带图备忘**：新建 → 加 4 张图 → 保存 → 打开详情，图片数应为 4，无破损占位
- [ ] **追加图片**：编辑该备忘 → 再加 1 张 → 保存 → 详情应有 5 张，**原有 4 张都在**
- [ ] **返回位置**：灵感页滚到中间 → 点开一条 → 返回 → 首个可见备忘应与点开前一致
- [ ] **切布局**：大卡片 ↔ 两列 ↔ 三列，各自回到自己上次的位置，不跳顶
- [ ] **搜索**：搜关键字、搜 `tag:xxx`、搜无结果，三种都有正确提示
- [ ] **编辑正文**：改一条备忘的文字并保存，列表与详情同步更新
- [ ] **删除**：删一条备忘，列表消失，资源页里它的图片也消失
- [ ] **切后台再回来**：位置与内容都还在
- [ ] 如果这版改了**离线/同步**相关：飞行模式下重复上面的建图/追加图，不应丢图

## 4. 发版

```bash
git tag -a <版本号> -m "MoeMemos <版本号>"     # 必须 annotated
git push origin <版本号>
```

- [ ] tag 格式符合 `X.Y.Z` 或 `X.Y.Z-beta.N`（工作流会校验并拒绝其它格式）
- [ ] 版本号语义：新功能 → `X.Y.0`；只修 bug → `X.Y.Z+1`
- [ ] Release 工作流绿，且 badging 断言通过（APK 内 versionName 必须等于 tag）
- [ ] Release 页面上 prerelease 标记正确（带 `-beta` 是预发布）

## 5. 发完之后

- [ ] 把版本号回填到对应需求条目的「实施记录」
- [ ] 如果这次推翻了某个决策，补一条 ADR
- [ ] 如果改了和上游重叠的文件，更新 [`upstream-divergence.md`](upstream-divergence.md)
