## 1. 产品定位

自托管的备忘录/灵感记录 App，可以两种用法：

1. **本地账户**：不连任何服务器，数据只在本机（可导出 ZIP）。
2. **远端账户**：连接自己部署的 [✍️memos](https://github.com/usememos/memos) 服务器，离线优先、联网自动同步。

面向「一类人自己用」，不做社交、不做推荐、不收集数据。这个定位决定了后面很多取舍
（例如没有分页、没有通知、没有账号体系）。

## 3. 导航结构

**有两套 NavHost**，这点很重要，改页面时最容易踩：

```
根 NavHost（startDestination = memos）
├── memos                      → MemosPage（抽屉容器，内含第二套 NavHost）
├── settings                   → 设置页
├── add-account / login        → 账户与登录
├── input?tag={tag}            → 新建备忘（可预填标签）
├── edit?memoId={id}           → 编辑已有备忘
├── share                      → 分享导入
├── resource                   → 资源页
├── account?accountKey={key}   → 账户详情
├── search                     → 搜索（根栈版本，供外部深链）
├── tag/{tag}                  → 标签页（根栈版本）
└── memo-detail?memoId={id}    → 备忘详情（根栈版本）

抽屉内子图（startDestination = memos）
├── memos     → 灵感页
├── archived  → 归档页
├── tag/{tag} → 标签页（带抽屉菜单的版本）
├── explore   → 发现页（仅远端账户）
└── search    → 搜索页
```

- 窄屏用 `ModalNavigationDrawer`，宽屏（≥ 展开断点）自动换成 `PermanentNavigationDrawer`，
  同一份 composition 通过 `movableContentOf` 迁移，导航状态不丢（`MemosPage.kt:43-57`）。
- 没有任何账户时，启动会强制跳到 `add-account` 并清空返回栈。
- **`tag/{tag}` 存在两份实例**（子图版带抽屉、根图版不带），返回栈互不相干。
- **子图页面跳根图页面必须用 `LocalRootNavController`**，用错会 `IllegalArgumentException`
  崩溃（`TagMemoPage.kt:136-143` 有注释记录）。

### 关键机制：「点开备忘」不是导航

灵感页 / 标签页 / 搜索页点卡片时，**不经过 NavController**，而是切换同一页内的
**list-detail 面板**（Material3 adaptive 的 `NavigableListDetailPaneScaffold`）：

- 宽度 < 840dp（手机）：单面板，详情整页替换列表；
- 宽度 ≥ 840dp（平板/横屏）：双面板，右侧显示详情。

这意味着：打开/返回备忘**不会改变路由**、不产生返回栈目的地；滚回列表时依赖滚动位置
恢复机制（见 §5.5），而不是导航栈。根图的 `memo-detail` 只被资源页和外部 intent 使用。

## 4. 页面逐页说明

### 4.1 灵感页（`memos`，标题「灵感」）

| 维度 | 说明 |
| --- | --- |
| 入口 | 启动默认页；抽屉第一项 |
| 顶栏 | 抽屉按钮（非永久抽屉才显示）／同步徽标（仅远端账户）／搜索／切换布局／排序 |
| 底部 | 扩展 FAB「新 MEMO」，列表在顶部时展开文字、滚动后收起 |
| 列表 | 三档布局，见 §5.1；卡片菜单见下 |
| 卡片菜单 | 置顶/取消置顶、编辑、分享文本、复制正文、复制链接（仅远端账户）、归档、删除 |
| 卡片内交互 | 勾选待办复选框会**直接改写正文并保存**；点标签跳标签页 |
| 下拉刷新 | 触发手动同步 |
| 空态 | 分三种成因给不同文案：搜索无结果 / 该标签下无备忘 / 完全没有备忘 |
| 错误 | 同步/加载错误以红字显示在列表顶部，下次成功加载自动消失 |
| 批量删除 | 二次确认，文案明确写「无法撤销」 |
| 底部留白 | 96dp 避让 FAB |

### 4.2 标签页（`tag/{tag}`）

结构与灵感页基本同构（点卡片开详情面板、长按多选、排序、切布局、搜索、下拉刷新）。

- 标题显示标签原文（保留 `#`）。
- 点另一个标签会在本页内跳转到那个标签；点当前标签不动作。
- FAB 新建会预填 `#tag `（带尾随空格，光标在其后）。
- 过滤规则是**大小写敏感的子串包含**（`content` 里含 `#tag` 或 `#tag/`）。

### 4.3 搜索页（`search`）

| 维度 | 说明 |
| --- | --- |
| 顶栏 | 不是普通 TopAppBar，而是 `SearchBar`：返回、输入框、有内容时的清除按钮；进入自动聚焦 |
| 搜索方式 | **边输边搜**，纯本地内存过滤（不发请求） |
| 范围 | 「包含归档」开关；查询里写 `is:archived` 会自动打开该开关 |
| 最近搜索 | 点历史标签回填；可一键清空历史 |
| 空查询 | 显示语法提示 |
| 结果 | 点卡片开详情面板；点标签跳标签页 |

搜索语法见 §5.3。

### 4.4 发现页（`explore`，标题「发现」）

- **只有远端账户能看到**：抽屉里按账户类型隐藏，路由层还有一层重定向兜底。
- 只读浏览服务器上的公共/工作区备忘，游标分页（每页 20）。
- **卡片不可点击**，进不了详情；不能点赞/评论/收藏。
- 顶栏只有抽屉与切换布局，没有搜索、没有排序、没有同步徽标。

### 4.5 归档页（`archived`）

- 列出已归档的备忘，卡片菜单：恢复 / 删除。
- 长按进多选，多选顶栏额外有「恢复」。
- **卡片点击是空实现** —— 归档页目前进不了备忘详情。
- 没有 FAB、没有排序、没有布局切换、没有搜索。

### 4.6 备忘详情

有两种打开方式：三页内的面板（正常路径）、根图 `memo-detail`（资源页与外部 intent）。

| 维度 | 说明 |
| --- | --- |
| 顶栏 | 标题「灵感」（`R.string.memo` 的中文值）＋ 返回 ＋ 更多菜单（与卡片菜单同项） |
| 内容 | 相对时间行（＋未同步云图标、可见性图标）、Markdown 正文（可选中复制）、**全部**附件图片 |
| 交互 | 勾选待办直接改正文；点图片进媒体查看器；点标签跳**根图**标签页 |
| 边界 | 备忘不存在 → 提示「未找到」；被删除/被移出列表 → 自动返回上一页 |

### 4.7 侧边抽屉

自上而下：统计（备忘数/标签数/天数）→ 活跃度热力图 → 「MoeMemos」标题 →
导航项（灵感 / 发现[条件] / 资源 / 归档 / 设置）→ 分隔线 → 标签列表（点进标签页）。

- 「资源」和「设置」跳根图，其余跳子图。
- 宽屏时抽屉常驻，`drawerState` 为 null，关闭动作是空操作。

### 4.8 媒体查看器（独立 Activity）

左右翻页、双指缩放 1–5 倍、双击 2.5 倍/复位、上下拖拽关闭、保存到相册、Live Photo 播放。

- 强制暗色主题、全屏隐藏状态栏。
- 加载中转圈，失败显示断图 + 文案。
- 同样受应用锁保护。

### 4.9 编辑器（`input` / `edit` / `share`）

详见 §6。

## 5. 跨页面的核心能力

### 5.1 列表布局（三档）

| 档位 | 形态 | 卡片内容 |
| --- | --- | --- |
| 大卡片 `LARGE` | `LazyColumn`，一行一条 | 预览正文（500 字符）+ 3 列正方形缩略图，最多 9 张，溢出在最后一张叠 `+N` |
| 两列 `TWO_COLUMN` | `LazyVerticalGrid`，2 列 | 固定高度卡片：2 行文字 + 3×2 缩略图（最多 6 张，溢出 `+N`） |
| 三列 `THREE_COLUMN` | 同上，3 列 | 同上，卡片更窄；高度按格宽动态算 |

- 切换方式：顶栏「切换布局」按钮点一次换下一档（大卡片 → 两列 → 三列 → 大卡片）。
- **布局是全局设置**，灵感 / 标签 / 发现三页共用同一份；搜索页与归档页不使用该设置，
  永远是列表形态。
- **只有灵感页把布局传给列表**；标签页虽然也显示切换按钮，但列表实际仍是列表形态
  （`MemosList` 的 `layout` 参数默认 `LARGE`，`TagMemoPage` 未传）。
- ⚠️ `Appearance.kt` 的注释写「三列刻意不显示图片」，但**首页三列仍然渲染 3×2 缩略图**：
  网格分支不看 `showResources`，`CompactGridBody` 也无此参数。该注释只在「发现」页成立。
  详见附录 B-1。
- 卡片高度固定用 `dense` 间距（4dp），大卡片用 15dp。

### 5.2 排序

- **3 种模式 × 2 个方向 = 6 种组合**：修改时间 `UPDATED` / 创建时间 `CREATED` / 字母 `TITLE`，各支持升序降序。
- 默认：创建时间 + 倒序。
- **置顶永远排在最前**，与模式、方向无关。
- 字母排序用 `java.text.Collator`（中文按拼音），比较的是**正文全文**（含 Markdown 符号），
  不是抽出来的标题。
- 排序按**账户**保存（换账户会换回该账户上次的选择）；布局是全局的，两者作用域不同。
- 排序对话框点选立即生效、不关闭对话框。

### 5.3 搜索与筛选语法

| 前缀 | 含义 | 细节 |
| --- | --- | --- |
| `tag:X` | 含该标签 | 前导 `#` 可有可无；**大小写敏感**的子串匹配（`#X` 或 `#X/`） |
| `is:pinned` | 仅置顶 | 只有 `pinned` / `archived` 两个值，其它 `is:xxx` 降级为普通关键字 |
| `is:archived` | 仅归档 | 会自动把归档数据纳入搜索范围 |
| `visibility:private\|protected\|public\|space` | 按可见性 | 忽略大小写 |
| `after:YYYY-MM-DD` | 该日**及之后** | 按 **UTC 零点**解释，不跟随本机时区 |
| `before:YYYY-MM-DD` | 该日**之前**（不含当天） | 同上；也接受完整 ISO-8601 |
| 其它文本 | 关键字 | 大小写不敏感的子串匹配 |

- 未知前缀（如 `foo:bar`）**不报错**，降级成普通关键字。
- 同一前缀写多次，**后者覆盖前者**（不合并）。
- 全部在内存里过滤，没有服务端搜索。

### 5.4 多选与批量

- 进入方式：**长按卡片**（注释里说"顶栏有按钮"，但实现是长按，见附录 B-2）。
- 多选态下：整卡点击=勾选、标题行出现复选框、菜单让位、编辑手势失效。
- 能做：全选/取消全选（**只作用于当前可见条目**）、批量删除（二次确认，不可撤销）；
  归档页额外有批量恢复。
- 退出：左上角 ✕，或批量执行完自动退出。
- 多选状态是页面级 `remember`，离开页面即丢失。

### 5.5 滚动位置

- 目标：点开一条备忘再返回，列表应回到原处。
- 机制：锚点存在 `MemosViewModel`（Activity 级，导航往返不丢），**纯内存、不写盘**。
- 锚点 key = 「页面 + 布局」，例如 `memos|LARGE`、`tag=假期|THREE_COLUMN`。
- 保存时机：滚动中持续采集（**`(0,0)` 一律不记**，防止列表重置产生的假值覆盖真锚点）；
  离开列表时再无条件记一次（覆盖"用户自己滚回顶部"）。
- 恢复时机：列表内容版本变化或布局变化时，且满足一串前置条件（当前确实停在顶部、
  锚点在当前列表里找得到、布局一致…）。
- 切换布局时：清掉该布局的旧锚点并回到顶部。
- 已知限制：进程被杀即丢失；历史上有过 8 个 beta 版本的反复，见
  [`../adr/ADR-001`](../adr/ADR-001-滚动位置锚点按页面与布局分桶.md)。

## 6. 备忘编辑器

### 6.1 能力

| 项 | 现状 |
| --- | --- |
| 正文 | 单个多行输入框；句首自动大写；无 Markdown 实时预览 |
| 格式按钮 | H1/H2/H3、粗体、斜体、删除线、无序列表、有序列表、清单 —— **共 8 个** |
| 回车续行 | 在列表/清单行内回车，会自动带上同样的前缀 |
| 清单切换 | 光标所在行在 `- [ ]` ↔ `- [x]` 之间切换（**单向**：`[x]` 不会再变回 `[ ]`，会变成 `- [ ]`） |
| 标签 | 没有独立数据结构，完全靠正文里的 `#tag`；按钮从已有标签下拉插入 |
| 可见性 | PRIVATE / PROTECTED / PUBLIC / SPACE；**本地账户不显示该项** |
| 附件 | 选图（最多 100 张，串行上传）、任意文件、拍照 |
| 图片排序 | 图片 >1 张时出现「调整图片顺序」对话框 |
| 关闭/发送 | 右上角 × 与 ➤；有文字或有附件即可发送 |

支持的 Markdown 语法就是上表那 8 种。**不支持**：引用、代码块/行内代码、表格、链接语法、
图片语法（图片走附件）、水平线、H4–H6、LaTeX。

### 6.2 两套互斥的保存机制

| 模式 | 开关 | 行为 |
| --- | --- | --- |
| 草稿 | 「自动保存」关闭（默认） | 退出时把正文写进该账户的**唯一一份草稿**；下次进入回填。草稿**不含附件、可见性、标签** |
| 自动保存 | 「自动保存」打开 | 正文/可见性/附件数一变就写库（**无防抖**，靠互斥锁串行）；退出时不再询问 |

退出确认只在「自动保存关闭」时出现，判据是正文变了或附件数变了 —— **只改可见性不会弹确认**。

> 注意区分两个「自动」：**自动保存**是把内容写进**本机数据库**（纯本地，全离线后仍然需要）；
> **自动同步**是把改动推送到**远端服务器**（没有开关，固定行为）。两者对照见 §15 末尾。

### 6.3 编辑器的边界行为

- 列表还没加载完（或进程被杀后重建）时打开"编辑"，会因为找不到备忘而**按新建处理**。
- 「丢弃更改」**不会回收已经上传的附件**，会留下孤儿附件。
- 自动保存模式下，图片排序**不会落库**（排序只在显式保存时写进时间戳）。

## 7. 附件与图片

### 7.1 从选图到出现在备忘里

```
选图 → 复制到应用私有目录 → 写 resources 表 → 保存备忘时回填 memoId → 列表/详情渲染
```

- 文件位置：`filesDir/resources/<账户标识>/<资源UUID>_<原始文件名>`。
- 数据库字段：`identifier`、`remoteId`（未上传时为 null）、`date`、`filename`（原始显示名）、
  `uri`、`localUri`、`mimeType`、`memoId`。
- **「顺序」没有独立字段，就是 `date`**：约定同一备忘内时间严格递增，读取时按 `date` 升序，
  文件名兜底。用户调整顺序＝保存时重新盖时间戳。

### 7.2 图片渲染规则

| 场景 | 规则 |
| --- | --- |
| 列表大卡片 | 3 列正方形，最多 9 张，溢出在最后一张叠 `+N` |
| 列表网格卡片 | 3 列 × 2 行，最多 6 张，溢出 `+N` |
| 详情页 | 3 列正方形，**全部显示、无上限、无 `+N`** |
| 加载失败 | 显示浅色底 + 断图图标（2.1.0 新增，此前是空白） |
| 加载中 | **没有任何占位或进度指示** |
| 点击 | 打开媒体查看器，可左右滑动看该备忘的全部图片 |
| GIF | 缩略图不播放，进查看器才动 |

### 7.3 删除附件

- 编辑器里：点图片/附件 → 「移除」→ 删文件 + 删数据库行（远端账户还会排队删服务端）。
- 详情页和资源页**没有移除入口**。
- 删除备忘时会一并删附件与文件（因为备忘是软删除，数据库级联**不会触发**，必须手动删）。

### 7.4 关于「丢图」这条历史

2.1.0 之前发生过两次静默丢图，根因都已修复，但改动相关代码时必须守住：

1. `updateMemo` **只增不删**。传入的附件列表来自调用方内存状态，可能陈旧，拿它当权威全集
   会连文件一起删。
2. 同步拉取时，**从没上传成功过（`remoteId == null`）的附件一律跳过**，不能删。
3. 建备忘与回填附件必须**在同一个事务里**。

## 8. 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `memos` | `identifier`(PK)、`remoteId`、`accountKey`、`content`、`date`、`visibility`、`pinned`、`archived`、`needsSync`、`isDeleted`、`lastModified`、`lastSyncedAt` | 列表、详情都读这张表 |
| `resources` | `identifier`(PK)、`remoteId`、`accountKey`、`date`、`filename`、`uri`、`localUri`、`mimeType`、`memoId` | 外键指向 `memos.identifier`，`onDelete = CASCADE` |

- 数据库版本 1，迁移列表为空，**刻意不用"破坏性迁移"**：本地账户下数据库就是全部备忘，
  宁可崩溃也不能静默清库。
- 备忘删除分两种：远端账户是**软删除**（`isDeleted`），本地账户是硬删除。
- 附件顺序靠 `resources.date` 表达（见 §7.1）。

## 9. 同步与离线

### 9.1 支持的服务器

| 方言 | 版本范围 | 说明 |
| --- | --- | --- |
| Memos V0 | ≥ 0.21.0 | 老 API |
| Memos V1 | 0.27.0 – 0.31.0 | 新 API；版本更高会要求用户确认「仍然登录」 |

判定方式：登录时先匿名打 V0 的 `/status`，拿不到版本再打 V1 的 `getProfile`。

### 9.2 什么时候同步

- **推送（本地 → 服务器）**：任何写操作后立即排队，串行执行。
  编辑器自动保存可延迟 2 秒去抖合并。
- **拉取（服务器 → 本地）**：进入列表页时自动拉一次（**5 秒内重复进入不重复拉**）；
  下拉刷新与顶栏徽标点击是强制拉取。
- **没有周期后台同步**。唯一的周期任务是桌面小组件刷新。

### 9.3 冲突怎么处理

按「本地改过没有」+「远端变过没有」分四种：

| 情况 | 结果 |
| --- | --- |
| 都没改 | 标记已同步 |
| 只有远端改 | 远端覆盖本地 |
| 只有本地改 | 推送本地 |
| 两边都改 | **复制本地版本成一条新备忘**（未关联），原地改成远端版本，再把副本推上去 |

- 删除冲突：本地软删但远端也改了 → 远端覆盖（备忘"复活"）；否则一起删。
- 远端把备忘删了：本地没同步过就重新创建；同步过且不是本轮新建 → 本地永久删除。
- 附件两个方向都不误删（见 §7.4）。

### 9.4 离线 / 失败时用户看到什么

| 场景 | 用户能看到 |
| --- | --- |
| 离线写备忘 | 正常保存，卡片显示未同步云图标；顶栏徽标显示未同步条数 |
| 手动同步 | 四种结果各弹对应对话框（版本不支持 / 需确认 / 失败 / 静默成功） |
| 拉取失败 | 列表顶部红字一行 |
| **自动同步失败** | ⚠️ **完全静默**，只有未同步计数会涨（见附录 B-4） |

## 10. 账户与登录

### 10.1 账户类型

| 类型 | accountKey | 说明 |
| --- | --- | --- |
| 本地账户 | `local` | 至多一个，可导出 ZIP，**不可删除** |
| Memos V0/V1 | `memos:<host>:<远端用户标识>` | 可多个 |

- 账户列表与全部设置一起存在 `settings_v3.json`。
- **Token 不写进这个文件**：持久化时被置空，实际存在 `secure_tokens.xml`（AES/GCM + AndroidKeyStore 密钥）。
- 切换账户会切换：备忘列表、标签、草稿、排序、编辑手势、自动保存、搜索历史。
  **不切换**：主题、字号、取色、图片品质、应用锁、列表布局、客户端证书。

### 10.2 登录流程

```
填 host + token → 必填校验 → host 补全（无 // 则补 https://）
→ 局域网权限（仅当 host 指向内网且系统要求）→ 匿名版本探测
→ 版本闸门 → 带 token 请求 → 存 token、写账户列表 → 进入列表
```

- 版本闸门：V0 < 0.21.0 不支持；V1 < 0.27.0 不支持；V1 > 0.31.0 需确认「仍然登录」。
- 失败呈现：snackbar（字段缺失 / 版本不支持 / 服务端错误）、对话框（版本过高）、
  专用对话框（局域网权限被拒）。

### 附：两个容易混的「自动」概念

因为这两个词很容易混，单独说明：

| 名称 | 是什么 | 数据去哪 | 全离线后还需要吗 |
| --- | --- | --- | --- |
| **自动保存**（设置里的开关） | 编辑器里每次改动就把内容写进**本机数据库**，退出时不再问「是否保存」 | 本机 Room 数据库 | ✅ **需要保留**，它是纯本地行为 |
| **自动同步**（没有开关，固定行为） | 把本机的改动**推送到远端 memos 服务器**；进入列表页时也会从服务器拉一次 | 远端服务器 | ❌ 全离线后失去意义 |

## 17. 产品方向：全离线化（已确认，未实施）

> 这一节不是需求，是**已确认的方向**，记在这里是为了让后续每个决定都有上下文。
> 等真正开工时，按 [`TEMPLATE.md`](TEMPLATE.md) 写成 `R-xxx-*.md`。

**目标**：移除全部在线功能，只保留本地账户，把 App 变成完全离线的单机备忘录。

### 会因此消失的东西

| 项 | 说明 |
| --- | --- |
| 账户体系 | 登录页、添加账户、账户详情、切换账户、退出登录（D-1 的数据删除风险随之消失） |
| 服务端版本探测与闸门 | V0/V1 判定、`0.21.0`–`0.31.0` 版本范围、强制同步确认 |
| 自动同步 | 推送、拉取、冲突处理（含"复制成新备忘"的冲突策略）、未同步徽标、待推送队列 |
| 客户端证书（mTLS） | 设置项、系统 Keychain 选择器、`mtls.xml` |
| 发现页 | 它读的是服务器上的公共/工作区备忘，无服务器即无内容 |
| 明文 HTTP / 用户 CA 风险（D-3） | 不再发请求，风险消失 |

### 会受影响、需要单独决定的地方

| 项 | 现状 | 全离线后要注意 |
| --- | --- | --- |
| **「上传图片品质」设置** | 压缩只做在**联网账户**的上传路径里（`SyncingRepository.createResource`）；本地账户直接用 `Instant.now()` 落盘、**不压缩** | ⚠️ 一旦只剩本地账户，这个设置会**完全失效**。要么把压缩挪到本地路径，要么删掉这个设置项 |
| 数据模型 | `memos.remoteId` / `resources.remoteId` / `needsSync` / `lastSyncedAt` 都是为同步服务的 | 可以留着不删（省一次迁移），但要知道它们不再有写入方 |
| 删除语义 | 远端账户是软删除（`isDeleted`），本地账户是硬删除 | 只剩一种语义后，软删除链路与"软删不触发级联"的坑一并消失 |
| 备份规则 | 排除 `secure_tokens.xml` / `mtls.xml` | 这两项不存在后，备份规则可以简化；但**数据库与附件仍在备份范围内**，需确认是否符合预期 |
| 导出 | 本地账户支持导出 ZIP | 全离线后这是**唯一的数据出口**，建议同期补上"导入"（当前没有） |
| 多账户 | 支持多个远端账户 + 一个本地账户 | 只剩一个账户后，账户切换相关状态（每账户的排序/手势/草稿/搜索历史）要不要保留需定 |
| 网络权限 | `INTERNET`、`ACCESS_LOCAL_NETWORK` | 若彻底不发请求，可考虑移除，但要注意别误删图片加载等仍需的能力 |

### 建议的推进方式

这一步会动到数据模型、仓库层、账户层和多个页面，属于**大改**。建议拆成几个需求分别做，
而不是一个 PR 全砍：

1. 先补"导入"（有了导入才有退路）
2. 再隐藏/移除在线入口（账户页、登录、发现页），代码先留着
3. 观察一段时间，确认真离线不影响使用
4. 最后才清理同步代码与数据模型
